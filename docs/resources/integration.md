# codemie_integration (Resource)

Manages saved CodeMie integration credentials for a user or project. Supported credential types are `Webhook`, `MCP`, `Scheduler`, `Jira`, `OpenAPI`, and `Git`.

Credential schemas vary by integration and deployment. The API accepts a JSON array of `{ "key": "...", "value": ... }` entries. The provider appends an `alias` entry when absent; if supplied, it must match the top-level `alias` attribute.

## Example Usage

```terraform
variable "jira_token" {
  type      = string
  sensitive = true
}

resource "codemie_integration" "jira" {
  scope           = "project"
  project_name    = "Engineering"
  alias           = "jira-main"
  credential_type = "Jira"

  credential_values = jsonencode([
    { key = "url", value = "https://company.atlassian.net" },
    { key = "token", value = var.jira_token },
    { key = "is_cloud", value = true },
  ])
}
```

## Import

Import IDs include the integration scope because the API has separate user and project operations:

```shell
terraform import codemie_integration.jira project/<integration-id>
terraform import codemie_integration.personal user/<integration-id>
```

For a user-scoped integration, set `scope = "user"` in the resource configuration before importing. The resource otherwise defaults to project scope.

The API masks sensitive credential values on reads. Imported resources require `credential_values` supplied in configuration; after import, run `terraform plan` to review the intended values before applying. Keep the configured JSON in a protected source or variable store.

## State Security

`credential_values` is marked sensitive, which hides it from normal Terraform CLI output but does not encrypt state. Use a protected remote state backend with access controls and encryption. Because CodeMie masks secrets in API responses, refresh cannot detect credential changes made outside Terraform. Terraform preserves the configured credential values in state; imported credentials cannot be recovered from the API.

## Scope Notes

- `scope` is `project` (the default) or `user`. Project integrations require `project_name`; user integrations omit it.
- `credential_type` must be one of the six supported values above.
- `is_global` defaults to false.
- The API does not expose typed credential schemas for every integration. `openapi_spec` is shown as a URL in the example; deployments that require an inline OpenAPI document can provide that document instead.
- This resource manages saved integration credentials only. It does not create MCP catalog servers, scheduled jobs, datasources, OAuth connections, or webhook actions.

## Credential Keys

The live deployment's tool configuration schema exposed these fields. Required fields and accepted values may differ between CodeMie deployments; the settings API validates them when the integration is saved.

- **Jira:** `url`, `token`, and `is_cloud`; username/authentication fields may be needed by other configurations.
- **Git:** `url` and `token`; `auth_type`, `access_token`, `refresh_token`, or host-specific fields may be needed.
- **Webhook:** `webhook_id` and `is_enabled`; resource and secure-header fields are optional integration settings.
- **MCP:** `url`; this is a credential record, not an MCP catalog server definition.
- **Scheduler:** `is_enabled`, `schedule`, `timezone`, `resource_type`, and `resource_id`.
- **OpenAPI:** `openapi_spec`; `is_basic_auth`, `openapi_username`, `openapi_api_key`, `auth_header_name`, and `timeout` are available.
